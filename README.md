# 在美华人资讯站

**读英文资料 → 自己写原创中文**。站点上只有原创稿件，不放外链、不做汇总页。

站点：https://yanbing2026.github.io/chinese-daily-brief/

## 为什么不做聚合

翻译和汇总**不产生任何我们拥有的东西**：文本不是我们的、不能主张版权、也没有议价能力。所以这条线彻底改掉：

- 采集来的英文材料只做**写作原料**，留在本地 `~/agents-workspace/default/us-chinese-brief/`，**不上站**
- 上站的每一篇都是原创中文写作（事实来自公开材料，表达是我们自己的）
- 页面里**没有外链**——读者不需要跳出去才能读完

## 生产线

1. `us-chinese-brief.py` — 采集 11 个栏目（USCIS / Federal Register / Google News 中英文 / 星岛美国 / Slickdeals），产出材料清单 + `latest.json`
2. `write-articles.py` — 按优先级挑材料 → 抓原文 → **写原创稿** → 验收 → 落盘
3. `brief-site-build.py` — 建站：首页 = 今日原创全文，另有往期原创

每小时（整点）由 cron 作业 `us-chinese-brief-publish` 跑完整条链，每轮 `write-articles --limit 2`
（每天每栏目仍上限 1 篇）+ `write-topics --limit 1`（选题去重按「日期+选题」，一天轮完 19 个 beat）。
写作与翻译走 **Nous Portal 免费档**模型，模型链只有一处出处：`~/.hermes/scripts/brief_llm.py`
（主力 `stepfun/step-3.7-flash:free`，备用 `ling-3.0-flash-fin:free` / `solar-pro4:free`；
注意免费档要求请求体带 `tags` 且含 `user=`，去掉 `:free` 后缀会静默走付费额度）。
`brief-publish.sh` 带 flock 单例锁：上一轮没跑完时本轮直接跳过。

## 验收规则（机械执行，不是靠提示词自觉）

| 规则 | 判定方式 |
|---|---|
| 长度 | 目标 1500–2800 汉字（硬门槛 800–4000；撑不到 800 字说明材料不够，宁可不出稿）|
| 中文化 | 统计汉字数 |
| 无外链 | 草稿里出现 `http(s)://` 或 `www.` 直接丢弃 |
| 禁止话术 | "点击这里""详见链接""本文由 AI 生成" |
| 数字不造假 | **三位以上**的数字必须能在原始材料里找到；找不到只**警告**不丢稿（2026-09-27 用户定：不纠结数字）|
| 同题多源 | 一篇报告要读**多家**报道：材料簇家数 + 同题补捞家数 ≥ 3，或 1 家政府全文；否则整条材料跳过（只有 1 条标题+摘要时模型会用通用知识编造）|
| 材料不足 | 模型回 `SKIP`，直接不出稿 |
| 事实纪律 | 年份/月份以材料为准；"已发布/已生效/已签署"这类断言必须有材料依据，预测不得写成既成事实 |
| 不点媒体名 | 正文与来源行都不得出现媒体/网站名（出处一律写"网络"，行文用"多家媒体报道""有报道称"）；政府与官方机构名必须保留 |

不合格的稿子**直接丢**，不拿空话填充。宁可少一篇。

## 撤稿：三处必须一起清

撤一篇稿要同时清 **① 库（Supabase）② `posts/index.json` 的 `posts` 与 `by_source` ③ `posts/*.html` 和繁体镜像 `tw/posts/*.html`**。
只删库不清索引，建站的"库里没有但本地有就并回站点"兜底逻辑（为写库失败时不丢稿而设）会把它重新上线。
另外：手工清理别和整点 cron 并发跑 —— 写稿脚本会用启动时读到的旧 `index.json` 覆盖回写，把刚清掉的条目复原。

## 目录

- `index.html` — 今日原创（全文）
- `posts.html` — 往期原创
- `posts/` — 单篇

采集来的材料与原始简报**不在本站**，它们在本地工作区里当原料。

## 已知边界

- 内容只做**信息整理**，不构成法律、税务或投资建议
- 移民、报税类数字以官方原文为准；稿件里的日期与金额均核对自材料
- Google/AdSense 对"规模化自动生成内容"有惩罚条款，所以策略是**每轮少量、有依据、可操作的稿子**，不刷量（每小时 2 篇材料稿 + 1 篇选题稿，且每栏目每天上限 1 篇）
