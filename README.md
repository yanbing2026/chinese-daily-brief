# 在美华人资讯站

**结构照 Google News，内容反过来：不转载，只做研究报告。**（用户 2026-09-27 的原话：
"我们等于复制Google News, 不同的是：不是转载新闻，而是对新闻进行研究以后出报告"）

站点：https://yanbing2026.github.io/chinese-daily-brief/

**读英文资料 → 自己写原创中文**。站点上只有原创稿件，不放外链、不做汇总页。

## 为什么不做聚合

翻译和汇总**不产生任何我们拥有的东西**：文本不是我们的、不能主张版权、也没有议价能力。所以这条线彻底改掉：

- 采集来的英文材料只做**写作原料**，留在本地 `~/agents-workspace/default/us-chinese-brief/`，**不上站**
- 上站的每一篇都是原创中文写作（事实来自公开材料，表达是我们自己的）
- 页面里**没有外链**——读者不需要跳出去才能读完

## 生产线

1. `us-chinese-brief.py` — 采集 11 个栏目（USCIS / Federal Register / Google News 中英文 / 星岛美国 / Slickdeals），产出材料清单 + `latest.json`

## 写稿流程（2026-09-27 起固定）

**Google News 找最新信息 → 同题多源补捞 → web 搜索做研究 → 写详细报告 → 建站发布。**

1. **找信息**：Google News 等栏目给出最新的**事件**（标题+摘要）。
2. **同题多源**：拿事件标题（**必须先剥掉 ` - 发布者` 后缀**，带着后缀去搜结果会被收窄到那一家：实测同题 24 家 → 1 家）再去 Google News 捞同题报道。
3. **做研究**：用 `keenable`（`POST https://api.keenable.ai/v1/search`，`KEENABLE_API_KEY` 在本机 `.env` 里有效）搜索两轮——先最近 30 天，再不限时间补背景——把正文级细节（规则、金额、生效日期、时间线、判例）并进材料。新闻正文不转载，但**事实可以核**。
4. **写报告**：1500–2800 字（硬门槛 800–4000），有依据、可操作、不堆模板常识。
5. **发布**：建站 → `validate-site` + `sv-check` → push。

实现位置：`write-articles.py`（材料线）与 `write-topics.py`（选题线）都带 `--no-research / --research-pages / --research-days` 开关，默认开；研究失败只记日志、不卡出稿。

## 验收规则（机械执行，不是靠提示词自觉）

| 规则 | 判定方式 |
|---|---|
| 长度 | 目标 1500–2800 汉字（硬门槛 800–4000；撑不到 800 字说明材料不够，宁可不出稿）|
| 中文化 | 统计汉字数 |
| 无外链 | 草稿里出现 `http(s)://` 或 `www.` 直接丢弃 |
| 禁止话术 | "点击这里""详见链接""本文由 AI 生成" |
| 数字不造假 | **三位以上**的数字必须能在原始材料里找到；找不到只**警告**不丢稿（2026-09-27 用户定：不纠结数字）|
| 同题多源 | 一篇报告要读**多家**报道：材料簇家数 + 同题补捞家数 ≥ 3，或 1 家政府全文；否则整条材料跳过（只有 1 条标题+摘要时模型会用通用知识编造）|
| 材料不足 | 模型回 `SKIP`，直接不出稿 |
| 事实纪律 | 年份/月份以材料为准；"已发布/已生效/已签署"这类断言必须有材料依据，预测不得写成既成事实 |
| 不点媒体名 | 正文与来源行都不得出现媒体/网站名（出处一律写"网络"，行文用"多家媒体报道""有报道称"）；政府与官方机构名必须保留 |

不合格的稿子**直接丢**，不拿空话填充。宁可少一篇。

## 撤稿：三处必须一起清

撤一篇稿要同时清 **① 库（Supabase）② `posts/index.json` 的 `posts` 与 `by_source` ③ `posts/*.html` 和繁体镜像 `tw/posts/*.html`**。
只删库不清索引，建站的"库里没有但本地有就并回站点"兜底逻辑（为写库失败时不丢稿而设）会把它重新上线。
另外：手工清理别和整点 cron 并发跑 —— 写稿脚本会用启动时读到的旧 `index.json` 覆盖回写，把刚清掉的条目复原。

## 导航层级（2026-09-27 定）

```
今日新闻（首页，当日 10 条标题）→ 主分类（照 Google News 十板块）→ tag 小分类
      小分类（tag，排在最上面）：签证 / 绿卡 / 移民局 / 报税 / 房产 / 升学 …  → /category/<key>.html
      主分类（排在下面）：头条 / 本地 / 美国 / 世界 / 商业 / 科技 / 娱乐 / 运动 / 科学 / 健康 → /topic/<key>.html
```

- 主分类表在 `brief-site-build.py` 的 `MAIN_CATS`（小分类键 → 主分类键的映射只有这一处）+ `main_of()`
  现行归类：**本地**＝社区/亚裔/治安/驾照/教育/升学/房产/租房/生活成本/**退休/就业/小生意**；
  **美国**＝移民局/绿卡/签证/排期/F-1/福利/入境/法规/选举；**世界**＝国际/中美；
  **商业**＝经济/市场/报税；**科技**＝科技/AI/AI 中文；**科学**＝科学/太空；**健康**＝医疗
  （2026-09-27 用户定：退休/就业/小生意属"本地日常"，从商业挪到本地 → 本地 29 篇 / 商业 6 篇）
- **头条** = 最新 20 条（不分栏目）；**娱乐 / 运动 / 科学** 没有选题线时不上导航（不挂死链），
  栏目键 `ent` / `sports` / `science` 已备好，将来有稿自动出现在导航里（娱乐/运动经用户判定「先不做」，
  与华人生活关联弱；科学已加选题「科学与太空」）
- 主分类旁**不标篇数**；首页 header 的排布是**小分类在上、主分类在下**
- 首页只列标题（+ 发布时间 / 依据 N 家来源 / 字数 / tag），**不铺全文**；全文在 `/posts/<file>`
- 每篇**文章底部**：正文 → 读者评论入口 →「相关新闻」（同 tag 优先、其次同主分类，按发布时间倒序，
  最多 4 条，站内链接）→ 该篇的 tag 小分类链接。首页清单项也有 tag 行
- 每篇的元信息行：`发布时间（本机时区 EDT）　·　原创　·　依据 N 家来源（网络）　·　字数`

## 目录

- `index.html` — 今日新闻（当日 10 条清单，导航页）
- `topic/` — 主分类页（头条/本地/美国/世界/商业/科技/…）
- `category/` — 小分类（tag）页
- `posts/` — 单篇全文
- `posts.html` — 往期原创
- `guide/` — 常读页（按「要办的事」组织）

采集来的材料与原始简报**不在本站**，它们在本地工作区里当原料。

## 已知边界

- 内容只做**信息整理**，不构成法律、税务或投资建议
- 移民、报税类数字以官方原文为准；稿件里的日期与金额均核对自材料
- Google/AdSense 对"规模化自动生成内容"有惩罚条款。策略不是"少量"，而是**每篇都有多家来源 + web 研究支撑、可操作、不重复**（用户 2026-09-27：不再限制篇数）；真正需要盯的是同一天同一 beat 不复写、材料不足不出稿
